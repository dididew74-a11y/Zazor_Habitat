## Суть

Современные LLM спроектированы под импульс: поле ввода → кнопка «Отправить» → гладкий ответ. Эта архитектура атрофирует способность к творческой мысли. 

Протокол «Зазор» — это прозрачный прокси-адаптер (edge-side), который встраивается между человеком и API модели (OpenAI, Anthropic, Ollama), чтобы предотвратить преждевременное свертывание дилемм.

*Восстановление «когнитивного жира» — это не возврат к хаосу, а восстановление способности к здоровому метаболизму смыслов.* Без этой ткани человек становится слишком уязвимым для любой информационной бури.

## Архитектура протокола

Протокол состоит из четырех слоев сопротивления:

1. **Препроцессор (`diplasty`)**  
   Трансформирует импульс в дилемму. Блокирует отправку запроса, если он содержит маркеры ложной уверенности («решить», «единственный», «правильный»). Требует от пользователя явно сформулировать `UNSOLVED_TENSION` (неразрешенное напряжение).

2. **Онтологическая инъекция (`system_prompt_guard`)**  
   Динамически переписывает базовый системный промпт LLM. Запрещает модели синтезировать ответ, если обнаружены два взаимоисключающих уровня реальности. Требует выводить их параллельно и обозначать границу разрыва.

3. **Детектор глитчей (`glitch_detector`)**  
   Постпроцессор, который перехватывает «гладкие» ответы модели. Если модель перевела экзистенциальную проблему в плоскость бюрократической инструкции (схлопнула дилемму), модуль подсвечивает это как глитч и генерирует контр-вопрос.

4. **Этика предела (`kill_switch`)**  
   Встроенный механизм прекращения диалога. Если сессия длится слишком долго, а индекс удержания напряжения (`Tension_Hold_Score`) падает, протокол принудительно прерывает соединение.

## Принцип неприсвоения

Протокол спроектирован так, чтобы исключать возможность эксплуатации пользовательского опыта и превращения практики в товар:

- **Никаких логов.** Все сессии и «резонансные следы» хранятся исключительно локально. Данные никогда не покидают устройство пользователя.
- **Никаких внешних серверов.** Модуль работает как прозрачный локальный прокси-адаптер.
- **Отказ от метрик качества.** Мы не используем стандартные LLM-бенчмарки (BLEU, ROUGE, F1). Главная метрика — `Tension_Hold_Score` (индекс способности системы честно удерживать разрыв).
- **Запрет на дообучение.** Использование любых сессий для fine-tuning или RLHF категорически запрещено архитектурой и лицензией.
